# Pi Desk rc.27 / Pith UI 0.2.2 preservation contract

This is the source inventory for the constrained-parts migration. It records the
old implementation before replacing it. It is not a new public scene API or an
instruction to preserve the old export boundary.

## Baselines and evidence

| Repository | Fixed baseline | Role |
| --- | --- | --- |
| Pi Desk / Pith Desk | `3f1ee24`, rc.27 | Actual callers, controller state, persistence and accepted product behavior |
| Pith UI | `897f46a83c637a3385adf91e281161cec157cf13`, `0.2.2` | Existing template structure, CSS, icons and owned UI state |

The Pith UI baseline was checked directly from the clean source checkout. All
source references below describe this commit. For an immutable source reference,
use `https://github.com/minifish-org/pith-ui/blob/897f46a/<path>` with the cited
line. Source references remain the contract when later source lines move.

Desk's production boundary is the `pith-ui/app` entry and `pith-ui/styles.css`.
Root factories used by Desk tests do not establish a production escape hatch.
The old application entry composes the blocks listed below; therefore all of
them, including nested previews, menus and loading surfaces, are migration
coverage. A screenshot of the initial workspace alone is insufficient.

Desk opens 17 independently owned surfaces through the old scenes: seven
workspace methods (`openMessageEditor`, `openQueueEditor`, `openConfirmation`,
`openWorkspacePicker`, `openRename`, `openFullAccess`, `openHistory`), six settings
methods (`openSettings`, `openConnections`, `openModels`,
`openConnectionLoading`, `openCustomConnection`, `openProviderLogin`), three
resource methods (`open`, `openEditorLoading`, `openEditor`) and one file method
(`openPreview`). Loading methods count separately because replacing the loading
opening must invalidate its target and preserve the later editor opening.

The Desk caller locations are under `frontend/src/` at rc.27:
`message-editor.ts:29`, `composer.ts:118`, `confirmation.ts:17`,
`conversations.ts:96,128`, `task-controls.ts:127`, `history.ts:10`,
`settings.ts:46,119,199`, `custom-connections.ts:11,18`,
`provider-login.ts:26`, `files.ts:100,120,165`, and
`resource-editor.ts:11,19`. Main assembly is `main.ts:40-81`.

Sources of truth, in order, are the old template, the complete CSS cascade,
owned state-update logic, and the actual Desk caller. Screenshots supplement
these sources by finding missing states, incorrect geometry or icon changes.
A screenshot cannot establish input retention, focus restoration, stale-result
protection, callback identity or teardown correctness.

The user's new contract supersedes the older `APP.md` rule requiring complete
workspace/settings/resources/files scenes and the root entry's unrestricted
composition permissions. The final published API must contain constrained parts
only. An assembly recipe is compiled documentation and internal verification
code, not a public factory for the old page or scene under another name.

## Shared presentation and behavior

The baseline imports `design.css`, then `primitives.css`, then the product rules
in `styles.css`. Later rules and containing surfaces affect actual presentation.
In particular, the final settings/form rules at `styles.css:531-560` override
earlier field spacing and sizing. Copying an early CSS rule does not reproduce
the final computed contract.

`src/forms/identity.ts:3` also adds `pui-control` to the native fields while
scoping IDs. The template string alone therefore omits a material class: its
display, disabled feedback and field rules are part of the actual form contract.

## Complete preservation inventory

Each numbered unit below needs a corresponding constrained-parts recipe and
internal assembly verification. Grouping nested helpers in one unit does not
remove their independent state or lifecycle cases. The names are audit IDs,
not proposed exported APIs.

### 01. Workspace frame

**Structure:** root application flex frame; sidebar with brand, workspace title
and add action, title search, navigation and bottom resources/connections/settings
actions plus reconnecting status. A sibling anchored context menu and sidebar
scrim precede `main`. Main owns topbar (mobile menu, folder/workspace/chevron/
conversation breadcrumb, Compact and artifact control), find bar, conversation
region, back-to-latest, and composer region. Composer panels appear in this
order: approval, workspace-busy, inline error, task failure, runtime/costs, queue;
then composer, image guidance and permission description. Completion notices,
copy status and fixed dialogs are root siblings.

**Layout:** viewport height, minimum 520px, hidden outer overflow; sidebar 260px
(230px below 1000px); topbar 79px; chat flexes and scrolls independently. Composer
is centered at `min(810px, 100% - 80px)`; messages at 774px; panel overflow is
separate from the input. Below 720px the sidebar becomes an overlay, topbar is
64px, minimum application height 420px, and composer/input rules narrow. Do not
add wrappers that alter flex children, direct-child selectors or intrinsic size.

**States/interactions:** workspace and conversation fallback labels,
reconnecting, scoped busy action, inline error, mobile open/closed, resize across
breakpoint. Opening mobile navigation focuses its first control, makes main
inert, traps Tab; Escape closes and restores the menu trigger. Pointer scrim
dismissal closes with BODY focused; breakpoint transitions restore the trigger
when the focused rail becomes inert. Closed mobile navigation is inert.
Child modal precedence remains. Shell-owned scopes combine
global, active, workspace and conversation availability without blocking an
unrelated inactive target. Compact retains the same action and is disabled for
missing/empty/running active conversation or the applicable host restriction.

Sources: `src/workspace.ts:117-265`, `src/app/index.ts:63-92`,
`src/app/workspace.ts:225-251,334-340`; CSS `src/styles.css:29-96,121-147,389-438`.

Every group also requires both appearances, applicable narrow/breakpoint cases,
and the shared presentation constraints. Final status should name the checks
actually completed and outstanding proof; do not convert this required-evidence
table into a claim that those checks passed.

For every inventory unit, the maintained recipe must include the complete part
tree, real compiling assembly code, typed state-to-part projection, callback
connections with target identity, explicit reset/edit semantics, and destruction
order. Examples should run as the internal acceptance fixtures rather than a
second, unverified documentation implementation. Reusable local assembly
functions may live in the consumer or example; exporting them as new public
whole-scene factories would fail the requested boundary.

The minimum reusable part capabilities exposed by this inventory are:

- Actions with finite primary/secondary/quiet/text/danger/selection semantics,
  content/icon/accessibility state and local pending; native button/submit/reset.
- Unwrapped and field-associated native text/search/URL/password/number/
  multiline/checkbox controls, composition-safe updates and explicit reset.
- Shared ordinary Select and an explicit finite native multi-row choice role.
- Text, heading, safely emphasized text, icon, semantic status/badge, image,
  sanitized Markdown, preformatted text and diff content.
- Finite row/column/grid/scroll/section/toolbar/action/footer/surface roles that
  preserve existing direct-child semantics; native form, details/summary,
  description-list and table structures without a wrapper around every node.
- Native modal and anchored surface/menu behavior, with finite library-owned
  surface purposes and focus/lifecycle ownership.
- Keyed collection and local async/lifetime mechanisms sufficient to retain the
  current input, row, disclosure, reading and pending-state behavior.

These are capabilities to prove, not permission for an open style DSL. Reject
raw HTML/markup factories, arbitrary `className`, `style`, CSS selectors, token
overrides, numeric gap/width/height/radius/font/animation arguments, and public
whole-workspace/settings/resources/files factories. A finite option named after
an entire former template is also a whole-template API if it hides the assembly.
Part interfaces should expose only content, bounded semantic choices, state,
callbacks and the minimal ownership/mount handles required for composition.

Existing root primitives cannot reproduce the old UI unchanged merely by
changing imports: general button/field/dialog structures differ from product
structures and their cascade. First add permanent proof for the difference;
then make a narrow reusable part/CSS change inside the library. Do not solve it
with consumer HTML/CSS copies, selector overrides, private import paths, broad
numeric layout options or one new wrapper per old node.

The inventory is complete only when every numbered unit is linked to a compiled
recipe and an executed assembly contract, including the interactions listed
above. A public-export check must inspect the actual tarball/declarations and
reject old scene/large-template/markup/visual-escape exports. An isolated

legal states and real interactions. Large combinations remain internal fixtures
and assembly documentation. Package build, tests, packed-artifact acceptance,
npm publication, downloaded registry verification, deployed showroom, Desk
region migration, main-branch merge and local native compile are separate
evidence. Report each explicitly; do not infer a later stage from an earlier
one.

Desk must finally pin the exact published version and assemble each region from
the documented parts, retaining its controllers, existing configuration,
conversations, colors and Logo. Preserve the existing Desk behavioral tests and
validate every replaced region before merging. A renamed public scene wrapper,
copied old HTML/CSS or consumer style override does not satisfy this contract.
