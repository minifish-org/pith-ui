# Validation

The frozen contract is `docs/contracts/rc27-ui-022.md`, based on Desk rc.27 `3f1ee24` and UI 0.2.2 `897f46a`. `docs/assemblies/coverage.md` maps every old region to its consumer-owned blueprint and permanent tests.

Run `npm run check`, `npm test`, `node scripts/verify-assemblies.ts`, `node scripts/catalog.ts`, `node scripts/api-docs.ts --check`, `npm run test:browser` and `npm run showroom:build`. Use distinct browser-test ports for separate checkouts. Keep the original Vite palette plugin when freezing a validation snapshot; otherwise equal old/new geometry does not prove the real color theme.

Assembly tests instantiate the actual old template, record native structure/computed styles and behavior, destroy its controllers, then mount the formal parts in equivalent inert context. Old delegates must not complete new interactions. Correct existing assertions stay. New behavior requires an explicit recorded exception; unit33 records the removed-row pending-copy defect and verifies both old and terminal formal branches.

The frozen DOM/style oracle is platform-specific. Its test reports the exact platform/browser requirement and explicitly skips on other environments. Cross-platform live old/new parity cases remain required. Chromium and WebKit proof does not imply physical iPhone Safari or human acceptance.

Retained old gallery and application fixtures are internal oracles and are not public exhibits, package entries or shipped scene implementations. The public showroom must contain only formal parts and legal states, with no whole application output.

Build the real package, pack it, and run `node scripts/release.ts verify`. This verifies the exact archive in an independent installation: root exports, declarations, CSS, private-import rejection, rejected presentation escapes, strict compilation of shipped assembly source/document examples and isolated production builds. Never substitute a source alias for installed artifact proof.

After publication, verify the registry artifact and install its exact version in Desk. Validate each migrated region and the whole application with existing configuration/conversations. Merge only after checks pass; build locally for the user's manual acceptance. Keep source validation, registry publication, consumer install, native build and manual acceptance as separate evidence.
